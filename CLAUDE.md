# CLAUDE.md — правила разработки

Проект разрабатывается ИИ-ассистентом. Эти правила обязательны.

## Источник истины
- Требования и архитектура — `docs/` (начинать с `README.md`). Код не должен противоречить документам:
  если реализация требует отступить — сначала обновить документ или добавить ADR в `docs/adr/`.
- Язык документации и интерфейса — русский. Код, идентификаторы, коммиты — английский.

## Открытые вопросы
- Реестр — `docs/open-questions.md`. **В начале каждого этапа роадмапа и в начале новой сессии** проверить его и задать
  заказчику вопросы, срок которых наступил (колонка «Нужно к этапу»). До ответа работать по колонке «Предположение».
- Новые вопросы, возникшие в работе, — добавлять туда же, а не только в чат.
- Заказчик отвечает в веб-штабе проекта https://claude.ai/artifact/VTKH9eTedipRYBNoyWaB9q (коллекции `questions`,
  `stages`, `ideas`, `log`, `engine`, `proposals`, `finding_ideas` в его базе). В начале сессии и этапа — прочитать ответы
  (`status: answered`), новые идеи (`source: client`) и предложения по движку (`proposals`, `status: new`) и идеи новых находок (`finding_ideas`, `source: client`),
  разобрать их, перенести в `docs/` и закрыть (`status: closed`, `resolution`; у предложений — `status` и `reply`).
  Описание модулей движка в `engine` держать в соответствии с `docs/12-analytics-engine.md`.
  Пороги движка — коллекция `engine_params` (значения в человеческих единицах: 75 = 75%, 0,5 = 0,5 п.п.); заказчик
  меняет их и отправляет запрос в `rebuilds` (`status: new`). Обработка: перенести значения в
  `backend/app/analytics/params.py` и `docs/12` (с переводом единиц), прогнать тесты и пересчет демо, затем в штабе
  `value = proposed`, `status: applied`, у запроса — `status: applied`, `applied_at`, `reply` (что изменилось в находках). После заметных изменений — обновить
  план (`stages`), бэклог (`ideas`) и журнал (`log`). Файлы в `docs/` остаются источником истины, штаб — их зеркало.

## Незыблемые принципы
1. **Цифры считает код, не LLM.** Любая метрика — детерминированная функция с unit-тестом. LLM получает только
   готовые результаты через инструменты; каждое число в тексте LLM проверяется по входным данным.
2. **Изоляция данных.** Каждый запрос — с контекстом тенанта и ресторана; RLS в Postgres включен всегда.
   Директор видит только свой ресторан и среднее по сети. Любой новый endpoint/инструмент чата — с тестом изоляции.
3. **Деньги** — `Decimal` / `NUMERIC`, никогда `float`. Количества — в базовой единице товара.
4. **Идемпотентность** импорта и пересчетов.
5. **Человек утверждает** все действия с последствиями (задачи, эксперименты).

## Стек
Backend: Python 3.12, FastAPI, Pydantic v2, SQLAlchemy 2, Alembic, Polars, arq + Redis, PostgreSQL 16.
Frontend: React + TypeScript + Vite, TanStack Query/Table/Router, Tailwind + shadcn/ui, ECharts.
LLM: Claude API через SDK `anthropic`, только через `backend/app/ai/gateway` (модели — ADR 0005).

## Рабочий процесс
- Порядок внутри задачи: тест/фикстура на демо-данных → сервис → API → клиент → UI → e2e.
- Перед коммитом: `make lint test` зеленые. Новые миграции — только через Alembic.
- Модули общаются через сервисы; `analytics` не импортирует `ai`.
- Промпты — файлы в `backend/app/ai/prompts/` с версией; изменение промпта → прогон eval.
- Небольшие коммиты с понятным сообщением; секреты — только в переменных окружения.
