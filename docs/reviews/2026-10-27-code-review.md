# Код-ревью и архитектурное ревью 27.10.2026 — конец этапа 3

Ревью кода после модулей M4–M7 и пересчета после загрузки (от `092ddd0`). Его провели два независимых
агента-ревьюера: один смотрел бэкенд, другой фронтенд. Ревьюеры кода не меняли. Исправления внес разработчик,
каждое — с тестом ([реестр](../13-testing.md)).

Чек-лист и метки — как в [ревью 26.10.2026](2026-10-26-code-review.md).

**Итог.** Блокеров нет. Найдено три серьезных дефекта, все исправлены:

1. директору через данные графика находки M3 уходили цены соседних ресторанов с названиями;
2. политики RLS новых таблиц позволяли директору записать сетевые KPI, тренд и журнал пересчетов;
3. пересчет после загрузки мог потеряться при гонке с воркером.

Во фронтенде экраны еще сами считали часть итогов (сумма «на столе», «в год», динамика тренда, вывод «Да/Нет»).
Теперь эти значения приходят из API. Прототип после действий расходился с правилами сервера: оставались кнопки,
которые создают дубли, директор видел стадию «Идет проверка» и имя проверяющего. Это тоже исправлено.

## Производительность и очередь пересчетов

Это не архитектурное ревью: здесь только замер движка и разбор очереди. Полное архитектурное ревью —
[27.10.2026](2026-10-27-architecture-review.md).

**Пересчет.** Пересчет движка ушел из HTTP-запроса:

- после публикации файла ставится в очередь (`analytics_runs`) и выполняется воркером arq;
- без Redis — фоном в процессе API;
- загрузки, пришедшие, пока пересчет ждет, присоединяются к нему;
- пересчеты одной сети идут по очереди (advisory lock);
- экран показывает «идет пересчет» и обновляется по завершении.

**Замер (TC-ENG-13).** Сеть из 108 ресторанов, 221 тыс. строк продаж: полный пересчет — 7 с
(после исправлений п. 11). Замер ручной, в CI не входит.

**Что остается на следующий этап:**

- движок читает всю историю фактов в память — окно по датам и агрегаты в SQL понадобятся на сетях с годами истории;
- RLS не в режиме `FORCE`: служебные команды владельца его обходят — до пилота;
- залежавшийся в очереди пересчет (воркер не запущен) не перезапускается сам — нужен периодический запуск arq
  (cron) вместе с развертыванием.
