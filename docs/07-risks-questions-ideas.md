# 07. Риски, вопросы, идеи

## Риски

| # | Риск | Почему важно | Что делаем |
|---|------|--------------|------------|
| R1 | **Качество данных** — нерегулярные инвентаризации, устаревшие ТТК, бардак с единицами | Мусор на входе = ложные инсайты = потеря доверия с первого показа | Модуль M7, Data Quality Score, `confidence` у каждого инсайта, честная пометка «недостаточно данных» |
| R2 | **Разная номенклатура** в ресторанах и системах | Без единого справочника нет сравнения точек | `ProductAlias`, нечеткое сопоставление + ИИ-подсказки + подтверждение человеком |
| R3 | **3 ресторана в пилоте** — слабая статистика для бенчмарков и экспериментов | Эффект может «не доказаться» или доказаться случайно | Бенчмарк по собственной истории и нормативам; эксперименты с контролем внутри ресторана; честные статусы |
| R4 | **Галлюцинации LLM** в цифрах | Одна выдуманная цифра перед инвестором — провал | Расчеты отдельно, tool use, пост-проверка чисел, evals в CI |
| R5 | **Три разные учетные системы** (iiko, r_keeper, 1С:ERP), у одной точки данные могут быть в двух системах | Разные коды блюд/товаров, разные форматы, риск двойного учета | Профили источников, таблицы соответствий кодов, правило «один набор данных — одна система-источник на ресторан» |
| R6 | **Сопротивление директоров** («ИИ-надзиратель») | Без их участия нет данных и исполнения задач | AI-сводка в тоне коуча, польза для директора (риски дефицита, чат), «что улучшилось», кнопка «не согласен» |
| R7 | **Расползание scope** | MVP не будет готов | Жесткие границы [00](00-vision-and-scope.md); автозаказ и прочие модули — после MVP |
| R8 | **Выгрузки «красивыми» отчетами** (шапки, итоги, группировки) | Импорт ломается на реальных файлах | Адаптивный парсер и профили источников; ранний тест на реальных файлах |
| R9 | **Полуфабрикаты и выходы** | Ошибки теоретического расхода | Рекурсивное раскрытие, проверка циклов, тесты на реальных ТТК |
| R10 | **Прозрачность между точками** — при 3 ресторанах обезличенное сравнение фактически раскрывает соседей | Конфликт между франчайзи | Формат сравнения выбирает УК (Q11) |
| R11 | **Стоимость LLM** при активном чате | Непредсказуемые расходы | Лимиты на пользователя, кэширование промптов, пакетная генерация сводок, мониторинг стоимости в `AiRun` |

## Принятые решения

| Вопрос | Решение |
|--------|---------|
| Учетные системы | iiko, r_keeper, 1С:ERP — данные через XLS/CSV, требования — [09](09-data-requirements.md) |
| Реальные выгрузки | Будут позже; импорт адаптивный (профили источников), стартуем на демо-сети |
| Пилот | 3 ресторана |
| LLM | Claude, отправка агрегированных данных в зарубежный LLM разрешена ([ADR 0005](adr/0005-llm-provider-abstraction.md)) |
| Директор | Ровно один ресторан |
| AI-автозаказ | Не в MVP; остается прогноз риска дефицита |
| Новое в MVP | AI-сводка директора и чат с ассистентом ([08](08-director-digest-and-chat.md)) |

## Открытые вопросы

1. **Q11. Что директор видит о других точках?** Варианты: (а) ничего, только свою динамику и нормативы;
   (б) обезличенно «лучшая точка сети / среднее» (при 3 ресторанах фактически узнаваемо); (в) открытый рейтинг всех трех.
2. **Q12. Какая система у каждого из 3 пилотных ресторанов** для продаж, склада и ТТК (например, продажи — r_keeper, склад — 1С)?
3. **Q13. Как часто реально проводятся инвентаризации** в пилотных ресторанах и полные ли они?
4. **Q14. Есть ли в ТТК полуфабрикаты** и ведется ли производство п/ф отдельными документами?
5. **Q15. Срок показа инвестору** — чтобы спланировать промежуточный показ (после этапа 5) или сразу полный.
6. **Q16. Кто дальше разрабатывает** (вы, команда, ИИ-ассистент) — влияет на уровень документации и автоматизации.

## Идеи, как усилить MVP

1. **Демо-сеть со «спрятанными» проблемами** — воровство мяса в точке №4, переплата поставщику в №7, «бумажные»
   инвентаризации в №2, устаревшая ТТК по всей сети. ИИ находит их на глазах у инвестора; это же — автотест детекторов.
2. **Главная цифра «Деньги на столе»** + счетчик «Подтверждено экспериментами».
3. **Карта процессов ресторана** в сводке — директор видит не таблицу отклонений, а какие процессы «текут».
4. **«Обсудить с ИИ»** из любого инсайта или пункта сводки — чат сразу в контексте проблемы.
5. **Telegram-бот директора** (после MVP) — сводка, задачи, алерты, фото-подтверждения.
6. **Меню-инжиниринг** — матрица «популярность × маржа» на тех же данных.
7. **Библиотека плейбуков** с историей эффекта — со временем ноу-хау продукта.
8. **«Раскрыть до накладной»** — любая цифра кликается до исходных строк.
9. **«Аудит за 1 день»** — клиент загружает 3 месяца данных и получает отчет с найденными деньгами; продающий вход в воронку.
