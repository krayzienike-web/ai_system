# 07. Риски, открытые вопросы, идеи

## Риски

| # | Риск | Почему важно | Что делаем |
|---|------|--------------|------------|
| R1 | **Качество данных** — нерегулярные инвентаризации, устаревшие ТТК, бардак с единицами | Мусор на входе = ложные инсайты = потеря доверия с первого показа | Модуль M7, Data Quality Score, `confidence` у каждого инсайта, честная пометка «недостаточно данных» |
| R2 | **Разная номенклатура** в ресторанах («Сыр моцарелла 1кг» / «Моцарелла Galbani») | Без единого справочника нет сравнения точек — главной фишки франшизы | `ProductAlias`, нечеткое сопоставление + ИИ-подсказки + подтверждение человеком |
| R3 | **Мало ресторанов для статистики** экспериментов | Эффект может «не доказаться» или доказаться случайно | DiD + bootstrap, фиксация дизайна заранее, честные статусы «не значимо» |
| R4 | **Галлюцинации LLM** в цифрах | Одна выдуманная цифра перед инвестором — провал | Расчеты отдельно, tool use, пост-проверка чисел, evals в CI |
| R5 | **Доступность и легальность LLM в РФ** (зарубежные API, 152-ФЗ, трансграничная передача) | Может блокировать продажи в РФ | `LLMGateway` с несколькими провайдерами (Claude / YandexGPT / GigaChat); в LLM — только агрегаты без ПДн |
| R6 | **Сопротивление директоров** («ИИ-надзиратель») | Без их участия нет данных и исполнения задач | Директор видит пользу для себя: прогноз дефицита, рекомендация заказа, рейтинг, бонусы за эффект |
| R7 | **Расползание scope** (HR, маркетинг, отчетность «всё сразу») | MVP не будет готов | Жесткие границы [00](00-vision-and-scope.md); остальное — витрина видения в UI |
| R8 | **Выгрузки разных учетных систем** сильно различаются | Импорт будет ломаться на реальных данных | Профили источников с маппингом колонок; ранний тест на реальных файлах (вопрос Q2) |
| R9 | **Полуфабрикаты и выходы** (вложенные ТТК, ужарка, разные брутто/нетто) | Ошибки теоретического расхода | Рекурсивное раскрытие, проверка циклов, тесты на реальных ТТК |
| R10 | **Безопасность данных франчайзи** — коммерческая тайна, утечки между точками | Юридический и репутационный риск | RLS, аудит, обезличенный бенчмарк для директоров |

## Открытые вопросы (нужны ответы до начала кода)

1. **Учетная система** сети: iiko, r_keeper, 1С, другое? Одна на всю сеть?
2. **Есть ли реальные выгрузки** (хотя бы 1–2 ресторана × 2–3 месяца, можно обезличенные)? Это главный ускоритель — проектирую импорт под них.
3. **Масштаб:** сколько ресторанов в пилотной сети, один бренд/меню или несколько?
4. **Инвентаризации:** как часто реально проводятся, полные или выборочные?
5. **ТТК:** есть полуфабрикаты? Ведется ли производство п/ф как документ?
6. **LLM и хостинг:** можно ли отправлять агрегированные данные в зарубежный LLM (Claude) или нужен российский провайдер / размещение в РФ?
7. **Директор** может управлять несколькими точками? Нужен ли франчайзи-владелец как отдельная роль уже сейчас?
8. **Срок** инвесторского демо — от этого зависит, идем полным роадмапом или «быстрым путем».
9. **Язык интерфейса** — только русский? Валюта — только ₽?
10. **Команда:** кто будет разрабатывать дальше (вы, команда, только ИИ-ассистент) — влияет на выбор стека и уровень документации.

## Идеи, как усилить MVP

1. **Демо-сеть со «спрятанными» проблемами** — синтетическая сеть, где заложены воровство мяса в точке №4,
   переплата поставщику в №7, «бумажные» инвентаризации в №2, устаревшая ТТК по всей сети. ИИ находит их на глазах
   у инвестора. Одновременно это автотест качества детекторов.
2. **Главная цифра «Деньги на столе»** — сумма эффектов всех открытых инсайтов + счетчик «Подтверждено экспериментами».
3. **AI-автозаказ** — рекомендация заказа по прогнозу (M6) — польза директору, а не только контроль. Снимает R6.
4. **Telegram-бот директора** — задачи, алерты о дефиците, фото-подтверждения. Директора живут в Telegram.
5. **Утренний дайджест** — 3 главных действия на сегодня для директора и сводка сети для УК.
6. **Меню-инжиниринг** — матрица «популярность × маржа» на тех же данных, сильный визуальный эффект.
7. **Библиотека плейбуков** — курируемые меры с историей эффекта по сети; со временем это ноу-хау продукта (data moat).
8. **Рейтинг ресторанов и геймификация** — индексы дисциплины, топ по фудкосту, бонусы директорам за подтвержденный эффект.
9. **«Раскрыть до накладной»** — любая цифра кликается до исходных строк: доверие к ИИ строится на проверяемости.
10. **Онбординг-отчет «Аудит за 1 день»** — клиент загружает 3 месяца данных и получает отчет с найденными деньгами.
    Это одновременно продающий инструмент (бесплатный аудит как вход в воронку).
