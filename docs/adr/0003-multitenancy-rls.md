# ADR 0003. Мультиарендность и роли: RBAC + scope + Postgres RLS

**Статус:** предложено

## Контекст
Продукт будет продаваться нескольким сетям (тенантам). Внутри сети директор видит только свои рестораны.
Утечка данных между франчайзи — критический риск.

## Решение
- `tenant_id` во всех таблицах, `restaurant_id` во всех операционных.
- `RoleAssignment(user, role, scope)`; права проверяются в API.
- Дополнительно Postgres Row-Level Security: на каждую транзакцию `SET LOCAL app.tenant_id / app.restaurant_ids`;
  приложение работает под ролью БД без `BYPASSRLS`.
- Директору сеть видна только агрегатно (медиана, перцентиль, свой ранг).

## Последствия
Два уровня защиты. Чуть сложнее миграции и тесты — нужен обязательный интеграционный тест изоляции.
