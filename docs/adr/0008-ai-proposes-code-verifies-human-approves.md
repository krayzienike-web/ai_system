# ADR 0008. ИИ предлагает, код проверяет, человек утверждает

**Статус:** принято (заказчик согласился с видением 27.10.2026)

## Контекст

Заказчик спросил, почему цифры считает код, а не ИИ, хотя «ИИ справится лучше». Ответ, с которым он согласился:

- цифра, по которой спрашивают с директора, должна быть воспроизводимой (одни данные — одна сумма);
- ее нужно уметь проверить до строки документа;
- сотни тысяч строк код считает за секунды, а нейросеть их не удержит и начнет обобщать;
- ошибку кода ловит тест, а уверенную ошибку нейросети никто не заметит.

При этом есть работа, которую правилами на Python не описать: свободный текст, незнакомые форматы, суждения о
причинах, поиск закономерностей, которых никто не закладывал. Здесь ИИ сильнее.

## Решение

Разделение труда для всех функций с ИИ:

1. **Цифры, по которым спрашивают с людей, считает только код** (принцип 1 CLAUDE.md, ADR 0002). ИИ получает
   готовые результаты через инструменты. Каждое число в его тексте сверяется с данными до показа.
2. **ИИ предлагает**: гипотезы, черновики, разметку, новые правила. Предложение помечено как предложение ИИ
   (`AiBadge`), рядом видно, на чем оно основано.
3. **Код проверяет**, что предложение не противоречит данным: размеченный файл проходит валидацию импорта,
   новое правило прогоняется на демо-сети и истории, цифры из текста сверяются с расчетом.
4. **Человек утверждает** все, что меняет данные, правила или работу людей (принцип 5): аналитик принимает
   разметку файла, вердикт по находке, новое правило; директор выбирает, что взять в работу.
5. ИИ вызывается только через `app/ai/gateway` (ADR 0005): промпты с версией, журнал запросов, eval-набор на каждую
   функцию. `analytics` не импортирует `ai`: движок работает и без ИИ.

## Что делаем (этап 5.5, после шлюза из этапа 5)

- **«Почему так» и «что делать».** Код нашел отклонение. ИИ по контексту (смена поставщика, меню, персонала,
  сезон, ремонт; история похожих находок и что тогда сработало) предлагает вероятные причины и как проверить каждую
  на месте, а также шаги с учетом правил сети. Например, цены в меню меняются только с новым меню раз в полгода:
  тогда находка по фудкосту идет в пакет к следующему меню, а не в «поднять цену сейчас».
- **Предпроверка находок для аналитика.** До ручной проверки ИИ помечает, на что посмотреть: праздники и
  банкеты, ремонт, смена поставщика, разовые всплески, похоже на ошибку выгрузки. Он готовит черновик вердикта с
  обоснованием. Вердикт ставит человек; статистика «ИИ предлагал / человек решил» — материал для настройки.
- **Поиск новых типов находок.** ИИ регулярно просматривает агрегаты (не сырые строки) и предлагает
  закономерности, которых нет в движке: «в R04 по пятницам растут списания мяса». Предложение попадает в «Идеи
  находок» штаба. Если аналитик подтверждает, мы пишем детерминированное правило с тестом, и оно становится
  модулем движка.
- **Новые форматы выгрузок.** Пришел файл с незнакомыми колонками или шапкой: ИИ размечает, какая колонка что
  значит, и объясняет почему. Человек подтверждает разметку один раз, она сохраняется как профиль источника, и дальше
  файл грузит обычный импорт со всеми проверками.

## Последствия

- Этап 5.5 в роадмапе (06) идет после шлюза ИИ (этап 5). На этапе 8 новые форматы выгрузок ускоряют
  подключение реальных выгрузок пилота.
- У каждой функции свой eval-набор на демо-сети, где правильный ответ известен из заложенных аномалий (docs/11),
  и свои тест-кейсы в реестре (docs/13).
- Остальные идеи из того же разговора — в бэклоге:
  - чтение договоров и прайсов;
  - причины списаний из свободного текста;
  - сопоставление названий по смыслу;
  - пакет к новому меню;
  - проверка отчетов директоров и фото-контроль.
