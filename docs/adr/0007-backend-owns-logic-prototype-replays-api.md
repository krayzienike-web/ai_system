# ADR 0007. Логикой владеет бэкенд; прототип проигрывает ответы API

**Статус:** принято (запрос заказчика 26.10.2026: «прототип и фронт равны, бэкенд владеет всей логикой»)

## Контекст

Прототип и фронтенд — один код: сборка прототипа отличается только транспортом (`VITE_DEMO=1`). Но 12 экранов
(обзор сети, «Моя неделя», находки, карточка находки, задачи, решения, проверки, рестораны, отчет, чат, счетчики меню)
брали данные из `src/mock/data.ts` и сами считали:

- суммы потерь и возможностей;
- тренд по неделям и рейтинг ресторанов;
- статусы процессов и «три дела недели»;
- этап работы по находке (дублируя `insights/work.py`);
- KPI и среднее по сети;
- ответы чата.

Действия (задачи, чек-листы, запуск проверок) жили в памяти браузера (`state/prototype.tsx`). Это противоречит
принципу 1 (цифры считает код на сервере) и делает прототип не тем же продуктом, что работает с данными.

## Решение

1. **Экран только показывает.** Все числа, статусы, ранжирование, тексты-выводы и решения «что показать» приходят из API.
   Во фронтенде остаются форматирование (₽, %, склонения), раскладка и состояние интерфейса: открыт ли блок,
   выбранный фильтр.
2. **API отдает готовые к показу данные экранов** (`/api/overview/...`), а не сырые таблицы: расчет — в сервисах
   `app/overview` поверх `analytics`, `insights`, `tasks`, `experiments`.
3. **Показатели, которым нужна вся сеть** (среднее по сети для директора), считаются при пересчете движка и хранятся
   снимком (`kpi_snapshots`). Директор видит снимок своего ресторана и среднее по сети, но не строки других ресторанов
   (RLS).
4. **Все действия — через API**: задачи, отметки чек-листа, отчет о выполнении, предложение и запуск проверки,
   тиражирование, вердикт проверки находки.
5. **Демо-данные — данные, а не код.** Витрина прототипа — это демо-сеть на бэкенде:
   - 12 ресторанов;
   - находки движка;
   - находки, заведенные аналитиком по заложенным аномалиям модулей M4–M7 (их ключи совпадают с будущими ключами
     движка);
   - история задач и проверок (`seed-demo`, `load-demo`).

   `src/mock/data.ts` и `src/mock/selectors.ts` удаляются.
6. **Прототип проигрывает записанные ответы API.**
   - `make demo-snapshot` поднимает демо-сеть, входит под каждым демо-пользователем, вызывает все GET-эндпоинты экранов
     и сохраняет ответы в `frontend/src/api/demo/snapshot.json`.
   - Демо-транспорт отдает их как есть.
   - Действия в прототипе меняют только сам затронутый объект: статус задачи, отметку, вердикт. Итоговые суммы
     остаются такими, какими их посчитал сервер в момент записи. Это видно в шапке, в том числе на телефоне:
     «Прототип · ДД.ММ».
   - Изменения накладываются так, как их увидел бы каждый пользователь по правилам сервера: директор не видит
     проверок и того, кто проверял находку; взятая в работу карточка уходит из «Моей недели»; вторая проверка
     той же находки и свой период вне записанных — ошибка 422, как на сервере.
7. **Числа для рисования — исключение из правила «деньги — Decimal» (код-ревью 27.10.2026).**
   Готовые данные графика находки (`findings.view`: шкала, состав, динамика) хранятся в JSONB как `float`: это точки
   для отрисовки, они не участвуют в расчетах и не складываются. Каждая сумма, которую показывают как цифру
   (эффект, «в год», итоги экранов, вывод словами), отдается отдельным полем в `Decimal` и считается из `Decimal`.
   Новое денежное значение в `view`, которое экран пишет текстом, а не рисует, — ошибка.
8. **Права в интерфейсе — по `permissions` из `/auth/me`.** Кнопку действия видит тот, кому сервер это действие
   разрешает (`useViewer().can(...)`); сервер все равно проверяет право сам. Ошибку действия экран показывает
   текстом сервера.
9. **Сверка.**
   - Тест-контракт (`backend/tests/test_demo_snapshot.py`) проверяет каждый записанный ответ по OpenAPI-схеме его
     маршрута: если поле переименовали, добавили или убрали без пересъемки, тест упадет.
   - Фильтры списка находок прототип применяет к записанному списку. `frontend/src/api/demo.test.ts` сравнивает
     результат с ответами сервера на записанных вариантах фильтров.
   - e2e-сценарии проходят на прототипе; интеграционные тесты API проверяют те же правила на сервере.

## Последствия

- Прототип показывает то, что реально посчитал бэкенд по демо-сети. Карточки находок модулей, которых еще нет
  (M4–M7), заведены аналитиком и помечены так. Когда модуль появится, движок заберет их себе по ключу.
- Чат до подключения LLM (этап с `app/ai/gateway`) отвечает детерминированно на сервере (`/api/chat`), по тем же данным.
  Шаблонный текст не помечается как ответ ИИ.
- Цифры прототипа обновляются только пересъемкой снимка (`make demo-snapshot`). Снимок входит в коммит, его изменения
  видны в ревью.
- Любой новый экран сначала получает эндпоинт с тестом изоляции, потом UI (порядок из CLAUDE.md).
