# ADR 0004. Канонная модель данных + адаптеры источников

**Статус:** предложено

## Контекст
MVP — загрузка XLS/CSV; потом — интеграции iiko, r_keeper, 1С. Нельзя, чтобы интеграции требовали переделки аналитики.

## Решение
- Единая каноническая модель (см. [01](../01-domain-model.md)), близкая к понятиям учетных систем.
- Источник → адаптер → staging → валидация → публикация в каноническую модель. Адаптер XLS использует сохраняемые
  профили маппинга колонок; API-адаптеры будут писать в тот же staging.
- У каждой записи — `source` и `import_batch_id`; публикация идемпотентна по (ресторан × период × тип данных).

## Последствия
Аналитика не зависит от источника. Добавление интеграции = новый адаптер.
