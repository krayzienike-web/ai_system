# 00. Видение и границы MVP

## Продукт целиком (north star)

AI-центр управления ресторанной франшизой. Четыре слоя:

1. **Данные** — единая модель данных сети из учетных систем (iiko, r_keeper, 1С, HR, CRM, отзывы).
2. **Аналитика и отчетность** — финансы, производство, запасы, HR, маркетинг, гость, сервис, качество.
3. **Цикл улучшений** — ИИ находит проблему → считает деньги → предлагает гипотезу → руководитель
   утверждает → задачи директорам тестовой группы → замер эффекта → тиражирование на сеть.
4. **AI-агенты** — автоматизируют ручную работу: менеджер запасов, HR, маркетолог, контроль качества и т.д.

Главная ценность для инвестора и клиента — **измеримые деньги**: «ИИ нашел X ₽/год, проверил на 3 ресторанах,
подтвержденный эффект Y ₽, тиражирование даст Z ₽».

## Почему MVP — менеджер запасов

- Фудкост — 25–35% выручки, самая большая управляемая статья. Отклонение на 1 п.п. = заметные деньги.
- Данные уже есть в любой учетной системе (продажи, ТТК, приходы, инвентаризации) и выгружаются в Excel.
- Эффект считается прямо в рублях, без сложной атрибуции.
- Сравнение ресторанов франшизы между собой (одно меню, одни ТТК) дает сильный бенчмарк, которого нет у одиночного ресторана.
- На этом же примере демонстрируется **весь цикл** (инсайт → эксперимент → эффект), а значит — архитектура всего продукта.

## Пользователи и роли (MVP)

| Роль | Видит | Делает |
|------|-------|--------|
| **Управляющая компания (УК)** | Все рестораны сети, сравнение, рейтинги | Загружает данные, смотрит инсайты, утверждает гипотезы и эксперименты, ставит задачи, видит эффект |
| **Директор точки** | Только свои рестораны (1..N) | Видит свои показатели и инсайты, получает задачи, отмечает выполнение, загружает свои данные |

Ролевая модель с самого начала строится как RBAC + область видимости (scope), чтобы потом добавить
роли «управляющий франчайзи с несколькими точками», «шеф-повар», «закупщик», «аудитор» без переделки.

## Что входит в MVP

1. **Загрузка данных из XLS/CSV** по шаблонам: справочники, ТТК, продажи, приходы, перемещения, списания,
   инвентаризации, остатки. Валидация, отчет об ошибках, повторная загрузка без дублей.
2. **Аналитика запасов (7 модулей)** — см. [02](02-analytics-spec.md):
   1. Исполнение ТТК (фактический vs теоретический расход)
   2. Фудкост (теоретический vs фактический, по блюдам и ресторанам)
   3. Контроль закупочных цен
   4. Контроль инвентаризаций
   5. Контроль списаний
   6. Прогноз риска дефицита и рекомендация заказа
   7. Качество данных
3. **Инсайты** — единый реестр находок с финансовым эффектом, приоритетом и объяснением от ИИ.
4. **Цикл экспериментов (тонкий)** — гипотеза → утверждение УК → задачи директорам → замер эффекта.
5. **AI-ассистент (чат)** — вопросы к данным на естественном языке в пределах прав пользователя.
6. **Дашборды** для УК и директора.
7. **Демо-сеть** — генератор синтетических данных со «спрятанными» проблемами для показа инвестору.

## Что НЕ входит в MVP (сознательно)

- Интеграции с iiko/r_keeper/1С по API (только архитектурная готовность: канонная модель + адаптеры).
- HR, маркетинг, гость, качество — только как «заглушки» в навигации для показа видения.
- Автоматическая отправка заказов поставщикам.
- Мобильное приложение (адаптивный веб достаточен; Telegram-бот — кандидат в MVP+, см. [07](07-risks-questions-ideas.md)).
- Биллинг, мультиязычность, SSO.

## Метрики успеха MVP

- Загрузка данных реальной сети (≥ 5 ресторанов, ≥ 3 месяца) проходит за < 30 мин без участия разработчика.
- На демо-сети ИИ находит ≥ 90% заложенных аномалий (это наш автотест качества).
- Каждый инсайт имеет: сумму эффекта в ₽, доказательство (цифры/график), объяснение, следующее действие.
- Полный цикл «инсайт → задача → замер» проходится в демо за 5 минут.
- Ни одна цифра в ответах ИИ не придумана моделью — все из расчетного слоя (проверяется тестами).
