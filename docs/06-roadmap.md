# 06. Роадмап MVP

Один план. Каждый этап заканчивается работающим, показываемым результатом (вертикальный срез), а не «слоем».
Оценки — ориентир для одного full-stack разработчика с ИИ-ассистентом.

| Этап | Содержание | Критерий готовности | Оценка |
|------|-----------|---------------------|--------|
| **0. Проработка** | Видение, доменная модель, аналитика, архитектура, требования к данным, ADR | Документы согласованы, открытые вопросы [07](07-risks-questions-ideas.md) закрыты | сейчас |
| **1. Фундамент** | Скелет репо, Docker Compose, CI, БД + миграции, auth, роли, RLS, тенанты/рестораны | `make up` поднимает систему; тест: директор не видит чужой ресторан ни через API, ни через БД | 1 нед |
| **2. Демо-сеть + импорт** | Генератор синтетической сети (10–15 ресторанов, 6 мес, заложенные аномалии); канонические шаблоны; пайплайн импорта, профили источников, отчет об ошибках | Демо-данные загружаются через UI; битый файл дает понятный отчет | 1,5 нед |
| **3. Аналитический движок** | Себестоимость, витрины, M1–M7, карта процессов, findings, эффект и приоритет | Детекторы находят ≥ 90% заложенных аномалий при ≤ 10% ложных | 2 нед |
| **4. Дашборды** | УК: «деньги на столе», сравнение ресторанов, инсайты, drill-down до накладной. Директор: свои KPI и инсайты | Сценарий демо проходится кликами | 1,5 нед |
| **5. Чат с ассистентом** | LLM Gateway, инструменты, стриминг, история, логирование, eval-набор | ≥ 90% вопросов eval-набора верно; 0 утечек чужих данных | 1,5 нед |
| **6. AI-сводка** | DigestBuilder, digest writer, карта процессов в UI, реакции директора, email; сводка сети для УК | Сводка формируется по расписанию; все числа сверены с расчетами | 1 нед |
| **7. Цикл экспериментов** | Гипотезы, три дизайна (вкл. контроль внутри ресторана), утверждение, задачи, замер | Полный цикл на демо-данных | 1,5 нед |
| **8. Пилот и демо** | Профили источников под реальные выгрузки iiko / r_keeper / 1С:ERP, загрузка 3 пилотных ресторанов, сценарий для инвестора, стенд в облаке | Реальные данные пилота загружены; демо за 10 мин без сбоев | 1,5 нед |

Итого ≈ 12 недель. Показ инвестору — по готовности MVP.

Реальные выгрузки можно подключить раньше: как только они появятся, профили источников под них делаются
параллельно с этапами 3–5 — это снижает риск этапа 8.

## Порядок разработки внутри этапа

1. Тесты/фикстуры на демо-данных → 2. backend-сервис → 3. API (OpenAPI) → 4. сгенерированный клиент → 5. UI → 6. e2e.

## После MVP

AI-автозаказ → API-интеграции iiko / r_keeper / 1С → Telegram-бот директора → модуль «Финансы (P&L)» →
AI HR (графики, текучесть, ФОТ) → маркетинг/гость (отзывы, CRM) → контроль качества (чек-листы, фото-аудит).
