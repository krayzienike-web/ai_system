# 06. Роадмап MVP

Один план. Каждый этап заканчивается работающим, показываемым результатом (вертикальный срез), а не «слоем».
Оценки — ориентир для одного full-stack разработчика с ИИ-ассистентом.

| Этап | Содержание | Критерий готовности | Оценка |
|------|-----------|---------------------|--------|
| **0. Проработка** | Видение, доменная модель, аналитика, архитектура, требования к данным, ADR | Документы согласованы, открытые вопросы [07](07-risks-questions-ideas.md) закрыты | сейчас |
| **1. Фундамент** | Скелет репо, Docker Compose, CI, БД + миграции, auth, роли, RLS, тенанты/рестораны | `make up` поднимает систему; тест: директор не видит чужой ресторан ни через API, ни через БД | 1 нед |
| **1.5. UX-прототип** | Кликабельный прототип обеих ролей на моковых данных: сводка директора, карточка находки, обзор сети, инсайты, эксперименты, задачи, загрузка данных, чат (сценарный). Типы моков = контракт API для этапов 3–7 (`frontend/src/mock/types.ts`) | Сценарии обеих ролей проходятся кликами; показ 2–3 директорам пилота | 1 нед |
| **2. Демо-сеть + импорт** | Генератор синтетической сети (10–15 ресторанов, 6 мес, заложенные аномалии); канонические шаблоны; пайплайн импорта, профили источников, отчет об ошибках | Демо-данные загружаются через UI; битый файл дает понятный отчет | 1,5 нед |
| **3. Аналитический движок** | Себестоимость, витрины, M1–M7, карта процессов, findings, эффект и приоритет | Детекторы находят ≥ 90% заложенных аномалий при ≤ 10% ложных | 2 нед |
| **4. Дашборды** | УК: «деньги на столе», сравнение ресторанов, инсайты, drill-down до накладной. Директор: свои KPI и инсайты | Сценарий демо проходится кликами | 1,5 нед |
| **5. Чат с ассистентом** | LLM Gateway, инструменты, стриминг, история, логирование, eval-набор | ≥ 90% вопросов eval-набора верно; 0 утечек чужих данных | 1,5 нед |
| **5.5. ИИ-помощник аналитика** | По [ADR 0008](adr/0008-ai-proposes-code-verifies-human-approves.md): «почему так» и «что делать» по находке; предпроверка находок перед ручной проверкой; поиск новых типов находок (идеи — в штаб, правило пишет код); разметка новых форматов выгрузок | На демо-сети: причины заложенных аномалий в топ-3 гипотез ≥ 80%; разметка незнакомого формата верна после одного подтверждения; ни одной цифры ИИ без сверки с расчетом | 1,5 нед |
| **6. AI-сводка** | DigestBuilder, digest writer, карта процессов в UI, реакции директора, email; сводка сети для УК | Сводка формируется по расписанию; все числа сверены с расчетами | 1 нед |
| **7. Цикл экспериментов** | Гипотезы, три дизайна (вкл. контроль внутри ресторана), запуск, задачи, замер | Полный цикл на демо-данных | 1,5 нед |
| **8. Пилот и демо** | Профили источников под реальные выгрузки iiko / r_keeper / 1С:ERP, загрузка 3 пилотных ресторанов, сценарий для инвестора, стенд в облаке | Реальные данные пилота загружены; демо за 10 мин без сбоев | 1,5 нед |

Итого ≈ 13,5 недели. Показ инвестору — по готовности MVP.

Реальные выгрузки можно подключить раньше: как только они появятся, профили источников под них делаются
параллельно с этапами 3–5 — это снижает риск этапа 8.

## Сделано раньше плана

По итогам разбора прототипа заранее сделан backend цикла работы (часть этапов 4 и 7): находки с этапом работы,
задачи с историей и результатом, запуск проверок, отчет для руководителя за период, фильтр периода
(`insights`, `tasks`, `experiments`, `reports`, `core/period.py`; [ADR 0006](adr/0006-tasks-execution-and-traceability.md)).
Находки пока создаются вручную / сидом — их начнет писать аналитический движок (этап 3). UI переключится с моков
на API на этапе 4 (сгенерированный клиент).

## Ход этапа 2

Сделано: генератор демо-сети (12 ресторанов × 6 мес, 12 заложенных аномалий с эталоном — [11](11-demo-network.md)),
модель справочников и фактов, импорт CSV/XLSX с поиском заголовков, единицами, отчетом об ошибках по строкам,
идемпотентной публикацией и откатом ([04](04-data-import.md#реализация-этап-2)), загрузка демо-сети через импорт.
Экран «Данные» работает на API: загрузка с отчетом по строкам, автоопределение вида файла, публикация и отмена,
свежесть данных по ресторанам, история. Сопоставление названий между системами: подсказки похожих позиций, подтверждение один раз, область действия
(сеть / ресторан), экран запомненных соответствий с пересчетом файлов. Полуфабрикаты в ТТК (вложенность, проверка
циклов, разворот блюда в сырье на дату) и перемещения между ресторанами. Остается: профили источников — после
реальных выгрузок (Q5). Этап 2 по сути закрыт; следующий — аналитический движок (этап 3).

## Порядок разработки внутри этапа

1. Тесты/фикстуры на демо-данных → 2. backend-сервис → 3. API (OpenAPI) → 4. сгенерированный клиент → 5. UI → 6. e2e.

## После MVP

AI-автозаказ → API-интеграции iiko / r_keeper / 1С → Telegram-бот директора → модуль «Финансы (P&L)» →
AI HR (графики, текучесть, ФОТ) → маркетинг/гость (отзывы, CRM) → контроль качества (чек-листы, фото-аудит).

## Этап 4. Дашборды — план (27.10.2026)

Большая часть экранов уже работает на API (см. «Сделано раньше плана» и этап 3). Чего не хватает до критерия
«сценарий демо проходится кликами»:

1. ~~Архитектурное ревью~~ (в работе) и исправления по нему.
2. ~~Честные подписи~~: типовые причины и меры не помечаются как ответ ИИ; «на 0% меньше» при неизменной динамике
   не показывается. ~~Демо: подорожание лосося и фудкост блюда подтверждены в истории~~ — главные деньги видны на
   «Сети»; на проверке — дефицит пасты и пропуск выгрузки.
3. **«Откуда цифры» до документа.** У каждой находки — исходные строки: накладные (дата, номер, поставщик,
   количество, цена, сумма), инвентаризации, списания с причиной, перемещения, продажи по дням; у строки — файл,
   из которого она пришла. Директор видит строки своего ресторана; сетевые находки по ресторанам — только УК.
4. **«Сеть»: рестораны × процессы.** Таблица потерь в ₽ по ресторанам и процессам (как в [10](10-ux.md), 4.3),
   клик по ячейке — находки ресторана по процессу. Показатели сети: фудкост, списания, переплаты поставщикам —
   с изменением к прошлому периоду.
5. **Меню «Еще» на телефоне** для УК: все разделы доступны с телефона (TC-UI-04).
6. **Сценарий демо** ([14](14-demo-scenario.md)): путь для показа за 10 минут; e2e проходит его целиком.
7. Схема архитектуры с технологиями (идея заказчика) — по итогам архитектурного ревью.
