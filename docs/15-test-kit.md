# 15. Тестовый набор выгрузок для стенда

Набор Excel-файлов нужен, чтобы до прихода настоящих выгрузок (Q5) пройти на стенде весь путь пилота руками.
Путь такой: загрузка через экран «Данные», сопоставление названий, отчет об ошибках, публикация, свежесть данных и
находки движка.

Файлы лежат в [`deploy/test-kit/`](../deploy/test-kit). Их пишет команда `python -m app.cli generate-test-kit`
(`backend/app/demo/test_kit.py`), и тест сверяет, что в репозитории лежит ровно то, что строит код.

## Что за данные

- **Сеть.** Отдельная сеть «Тестовая сеть»: 3 ресторана (R01 — Тверская, R02 — Арбат, R03 — Невский), 16 товаров
  и полуфабрикат, 12 блюд, 8 поставщиков.
- **Период.** 9 недель: 17.08–18.10.2026. На стенде «сегодня» — 20.10.2026 (`DEMO_TODAY`).
- **Откуда цифры.** Их дает генератор демо-сети ([11](11-demo-network.md)) с теми же заложенными проблемами, так
  что заранее известно, что движок должен найти.

### Чем файлы похожи на настоящие выгрузки

Файлы отличаются от наших шаблонов ([04](04-data-import.md)) так же, как настоящие выгрузки:
- над таблицей — название отчета, ресторан и период;
- колонки названы как в учетных системах: «Артикул», «Кол-во блюд», «Сумма со скидкой», «Официант»,
  «Контрагент», «Номенклатура», «Статья списания», «Кто удалил»;
- даты и числа записаны как настоящие значения Excel, а внизу — строка «Итого»;
- приходы — в форме 1С: без кодов товаров, поставщик указан по названию;
- у R02 приходы в граммах, а у пяти товаров — названия из 1С («Моцарелла фиор ди латте 45%»,
  «Филе куриное охл.» …).

Пустых колонок нет.

| Папка | Файлы | Куда загружать |
|-------|-------|----------------|
| `1 Справочники сети` | Рестораны, Номенклатура (iiko), Поставщики (1С), Блюда (iiko), Техкарты (iiko) | «Куда» — **вся сеть**, строго по порядку номеров |
| `2 R01 на Тверской`, `3 R02 на Арбате`, `4 R03 на Невском` | Продажи (r_keeper), Приходы (1С), Списания, Инвентаризации, Остатки на дату (iiko), Удаления (r_keeper) | «Куда» — **этот ресторан** |
| `9 Файлы с ошибками` | Продажи R02 с тремя ошибками; приход R01 с единицей «упак» | R02 и R01 соответственно — посмотреть отчет; загрузить не получится |

## Как подготовить стенд

```sh
cd ai_system/deploy
docker compose run --rm worker python -m app.cli seed-test-network --password '<свой пароль>'
```

Команда создает пустую «Тестовую сеть» со входами `admin@test.local`, `analyst@test.local` и
`director1@test.local` … `director3@test.local` (R01…R03). Пароль у всех — тот, что указан в команде: от 10
символов и не `DEMO_PASSWORD`, который раздают гостям демо.

- Демо-сеть не затрагивается.
- Ночной сброс демо пересобирает только демо, а тестовую сеть оставляет.
- Начать заново: `seed-test-network --reset --password '…'` — удаляет тестовую сеть со всеми загрузками и
  создает пустую.
- Тестовая сеть — только для синтетических файлов этого набора. Настоящие выгрузки пилота сюда не загружаем:
  для пилота — отдельная конфигурация без демо-календаря (см. отчет ревью перед пилотом, п. 4).

Файлы на свой компьютер: папка `deploy/test-kit` на GitHub или архив из чата.

## Как проверять

Вход — `admin@test.local`, экран «Данные». «Что в файле» оставляем «Определить по файлу»: система сама узнает
файл по заголовку.

1. **Справочники**, по порядку, «Куда» — вся сеть.
   - В отчете «Мы поняли файл так» видно, какие колонки узнаны, и строку заголовков (4-я).
   - «Загрузить в систему».
2. **R01, затем R03** — шесть файлов каждого ресторана.
   - В отчете — период 17.08–18.10; у продаж, приходов и удалений — предупреждение о пропущенной строке «Итого».
   - После публикации таблица свежести показывает ресторан «по 18.10».
   - Находки пересчитываются в фоне после каждой загрузки.
3. **R02 — «Приходы (1С)»: статус «Нужно сопоставить названия».** Система не подставляет похожее молча, а
   предлагает до трех вариантов. Правильные ответы:

   | Название в 1С | Товар сети |
   |---------------|-----------|
   | Моцарелла фиор ди латте 45% | Сыр Моцарелла |
   | Филе куриное охл. | Куриное филе |
   | Лосось атлантический охл. (филе) | Лосось охлажденный |
   | Руккола свежая, кг | Руккола |
   | Масло оливк. Extra Virgin | Масло оливковое |

   - «Запомнить и проверить снова» → файл проверен, граммы переведены в килограммы → «Загрузить в систему».
   - Соответствия появятся в «Какие названия мы запомнили?».
4. **Файлы с ошибками.**
   - Продажи R02: ошибки в строках 9 (отрицательное количество), 16 (дата в будущем) и 30 («много» вместо
     числа). Файл не загружается целиком.
   - Приход R01: «неизвестная единица «упак» у товара «Сыр Моцарелла»».
5. **Повтор.** Тот же файл второй раз для того же ресторана система отклоняет как уже загруженный. Можно отменить
   любую загрузку в «Что загружали?»: данные периода вернутся из более ранних файлов.
6. **Находки.** «Проверка находок» (вход УК). Пока движок новый, находки сначала проходят сверку аналитика
   ([ADR 0009](adr/0009-findings-reach-directors-through-hq-decision.md)). Должны появиться:

   | Модуль | Находка |
   |--------|---------|
   | M1 | Перерасход по техкарте: сыр моцарелла (R01); лосось охлажденный (R03); техкарта картофеля фри, вероятно, устарела (вся сеть) |
   | M2 | Фудкост выше целевого: «Лосось на гриле»; «Куриные котлеты» популярны, но мало зарабатывают; «Пицца Четыре сыра» выгодна, но ее редко берут |
   | M3 | Закупка у дорогого поставщика: говядина (R02); цена масла оливкового выше прежней |
   | M4 | Больше половины списаний оформлено за 2 дня до инвентаризации (R01) |
   | M5, M6 | Списания рукколы выше сети и затоваривание (R01) |
   | M7 | «Тыквенный суп» продается без техкарты; цены в накладных похожи на ошибку (R03, строка без суммы) |

7. **Директор.** Вход `director1@test.local` показывает только R01, и только те находки, по которым УК поставила
   задачу.

Этот путь проходит автотест `backend/tests/test_test_kit.py` (TC-DEMO-09…11): все файлы загружаются без выбора
шаблона, ошибки — в строках 9, 16 и 30, движок находит заложенные проблемы, а ночной сброс оставляет тестовую сеть.
