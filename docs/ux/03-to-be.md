# 03. To-Be: видение интерфейса SousChef AI

Основано на: аудите ([01](01-cjm-job-stories-audit.md)), бренде и дизайн-системе ([02](02-brand-design-system.md)),
исследовании практик ([research/ux-best-practices.md](../research/ux-best-practices.md)) и конкурентов
([research/competitors.md](../research/competitors.md)).

## 1. Идея

**Интерфейс — это су-шеф, который каждую неделю приносит управляющему подготовленный план:**
какой потенциал прибыли, три главных дела, доказательства и готовые черновики решений. Человек читает вывод,
проверяет при желании до накладной и нажимает одну кнопку.

Три отличия, которые интерфейс должен делать видимыми (их нет у конкурентов):
1. **Деньги и действия вместо отчетов:** каждая находка — сумма в рублях, причина, шаг.
2. **Замкнутый цикл:** находка → задача → проверка на части ресторанов → подтвержденный результат в ₽.
3. **Проверяемость:** любая цифра раскрывается до документа; текст ИИ помечен и отделен от посчитанных цифр.

## 2. Принципы (сводка исследований)

| # | Принцип | Откуда |
|---|---------|--------|
| 1 | Каждый блок: вопрос → вывод одной фразой → визуализация → одно действие → откуда цифра | Аудит 6.5, NN/g, Apple HIG |
| 2 | Нет числа без сравнения (норма, сеть, прошлая неделя); направление словами «лучше / хуже» | UX-практики §1 |
| 3 | Деньги словами: «теряем 38 тыс ₽ в месяц», а не «−38 тыс ₽/мес» | Аудит 6.1 |
| 4 | Статус = цвет + иконка + слово | WCAG 1.4.1, Carbon |
| 5 | Метка «ИИ» на тексте модели с окном «Почему я это вижу»; посчитанные кодом цифры — без метки, с пометкой «посчитано по данным» | IBM Carbon AI label, HAX |
| 6 | Уверенность — категория и причина («высокая — 2 полные инвентаризации») | Apple HIG, HAX G2 |
| 7 | ИИ предлагает, человек утверждает: предпросмотр действия (что, кому, срок, эффект), отмена в течение нескольких секунд | Square, Nory, Smashing 2026 |
| 8 | Чат открывается из карточки, отвечает таблицей или графиком и кнопкой «Создать задачу» | Crunchtime AI Analyst, Toast IQ |
| 9 | Директору — «что сделать в ресторане», УК — «что системно проседает в сети» | Fourth iQ 3.0 |
| 10 | Тренд за 8 недель с выводом под графиком | Poster Food Cost Control |
| 11 | Движение — только когда что-то меняется или нужно показать порядок чтения; уважать `prefers-reduced-motion` | Apple HIG Motion |
| 12 | ПК в первую очередь; на телефоне — нижние вкладки, карточки вместо таблиц, цели касания от 44 px | UX-практики §7 |

## 3. Информационная архитектура

### Директор
| Раздел | Ответ на вопрос |
|--------|-----------------|
| **Моя неделя** | Потенциал прибыли, что сделать в первую очередь, где теряем, как я против сети |
| **Задачи** | Вся работа ресторана в одном месте: дела из сводки, задачи от УК и задачи проверок; что сделано и какой результат |
| **Все находки** | Полный список по моему ресторану с фильтром по процессу |
| **Данные** | Что загружено и когда, загрузка новой выгрузки |
| Су-шеф (кнопка вверху, Ctrl K) | Любой вопрос по данным |

### Управляющая компания
| Раздел | Ответ на вопрос |
|--------|-----------------|
| **Сеть** | Потенциал прибыли, становимся ли лучше, кто и где теряет |
| **Ждут решения** | Что требует моего решения: проверки к запуску, черновики проверок, просроченные задачи |
| **Находки** | Рабочее место УК: все находки сети и работа по каждой — задачи директорам, проверка, результат. Фильтр по этапу «Новые → Делаем → Проверяем → Есть результат» и «Есть просрочки». Отдельных разделов «Проверки» и «Задачи» у УК нет: проверка и задачи открываются из своей находки |
| **Рестораны** | Общий список с поиском и сортировкой (потери, просрочки, выполненные задачи) и страница ресторана |
| **Отчет для руководителя** | Нашли / сделали / подтвержденный эффект — одна страница |
| **Данные**, **Нормы и настройки** | Загрузки и нормы потерь, целевой фудкост |

## 4. Ключевые экраны

### 4.1 «Моя неделя» (директор)
1. **Главная сумма:** «Найденный потенциал прибыли 128 тыс ₽ в месяц · в N находках →» (нарастающая цифра) и изменение за неделю словами.
   Ниже — одна полоса «Потери / Упущенная выгода» с суммами и пояснением, из чего каждая состоит.
2. **«С чего начать на этой неделе»:** три карточки-дела (сумма, одна фраза, срок, кнопка «Взять в работу»).
   Взятое дело анимированно уходит в «Задачи», счетчик задач обновляется.
3. **«Может не хватить до поставки»** — узкая полоса-предупреждение, только когда есть риск: «моцарелла — закончится
   за 2 дня до поставки» + «Предупредить закупщика».
4. **«Где ресторан теряет деньги?»:** процессы с потерями списком по убыванию суммы (полоса, число находок, их названия);
   клик раскрывает находки на месте. Процессы без потерь — одной строкой «В норме: …».
5. **«Как я против сети»:** шкалы «я / сеть / норма» по фудкосту и списаниям с выводом словами.
6. **«Что дали ваши задачи?»:** выполненные задачи и результат каждой в рублях.

Одна колонка, без боковой панели: блоки идут в порядке чтения и не спорят за внимание.
7. **Текст недели от ИИ** — с меткой «ИИ» и окном «Почему я это вижу».

### 4.2 Карточка находки
Сверху: путь цикла «Нашли → Делаем → Проверяем → Результат». Затем:
1. Вывод одной фразой и сумма словами.
2. Шкала «я / сеть / норма».
3. «Из чего сложилась потеря»: одна полоса (по техкартам / списано / не объяснено) и формула словами.
4. График с выводом над ним.
5. «Почему так» (ИИ, с меткой) и «Что сделать» — шаги с выбором.
6. Действия: «Взять в работу» (окно: шаги, срок, предпросмотр задачи), у каждого шага «Что сделать» — быстрая задача
   в один клик (УК ставит директору), «Спросить су-шефа». Оспаривания нет ([ADR 0006](../adr/0006-tasks-execution-and-traceability.md)).
7. «Что сделали и что получилось?» — история каждой задачи: нашли → поставили → выполнили (отчет) → результат в ₽.
8. «Доказательства» — таблица документов, свернута.

### 4.3 «Сеть» (УК)
1. Главная сумма «Найденный потенциал прибыли» (сети) + «Подтвержденный эффект (по итогам проверок)».
2. График 8 недель: «потенциал прибыли» снижается, «подтвержденный эффект» растет — вывод словами.
3. «Ждут вашего решения» — 1–3 карточки с кнопками прямо в блоке.
4. «Кто теряет больше» — рейтинг ресторанов с изменением за неделю.
5. «Общие проблемы сети» — один список: процессы, проблемные в нескольких ресторанах, и сетевые находки (ошибка ТТК).

### 4.4 Проверки
- Отдельного списка нет: проверка — этап работы по находке. Запуск — в «Ждут решения», ход и итог — в карточке находки
  и на странице проверки (открывается из находки).
- Мастер из находки в 3 шага: «Что меняем» → «Где пробуем и с чем сравниваем» (система предлагает контрольные
  рестораны) → «Сколько ждем и что считаем успехом» → предпросмотр задач директорам → «Передать на запуск».
- Результат: крупный вердикт «Сработало / Не сработало / Пока непонятно», сумма и диапазон словами
  («скорее всего от 3 до 7 тыс ₽ в месяц»), график «где пробовали / с чем сравнивали», кнопка «Предложить всем ресторанам».

### 4.5 Отчет для руководителя
Три числа крупно и полной суммой (не «тыс ₽»): **Найденный потенциал прибыли**, **В работе**, **Подтвержденный эффект** — ₽ в месяц
и в год. Затем: «Какая динамика по находкам?» (открытые / закрытые находки, изменение потенциала, график за выбранный период),
«Что сделали и что получилось?» (задача → результат), **«Что не получилось?»** (проверки без эффекта, задачи без результата,
просрочки — с причиной), «Что проверили?». Одна страница, которую можно показать на совещании.

Период для всех экранов выбирается в верхней строке (готовые периоды по полным неделям или свои даты), правила — в
[02-analytics-spec](../02-analytics-spec.md#период-отчета).

## 5. Движение и «вау» (функциональное)

| Момент | Эффект |
|--------|--------|
| Открытие недели | Сумма нарастает, блоки появляются по порядку чтения |
| «Взять в работу» | Карточка сжимается и улетает в «Задачи», счетчик подпрыгивает, всплывает уведомление с «Отменить» |
| Шкалы и рейтинг | Заполнение полос при появлении |
| Цикл находки | Прогресс этапов заполняется по очереди |
| Навигация | Подсветка активного раздела «переезжает» |
| График сети | Линии «рисуются» слева направо |
| Су-шеф | Панель выезжает, ответ печатается, таблица появляется после текста |

## 6. Что меняется в данных (контракт)

`frontend/src/mock/types.ts`: у находки — `headline` (вывод простыми словами), `scale` (я / сеть / норма),
`composition` (из чего сложилась потеря), `chart.conclusion`; у задачи — `assignedBy`, `createdAt`, `doneAt`, `report`,
`outcome` (результат в ₽, считает аналитика; [ADR 0006](../adr/0006-tasks-execution-and-traceability.md));
тренд сети `WeeklyTrend`. Эти поля должен отдавать расчетный слой (этапы 3–6).
