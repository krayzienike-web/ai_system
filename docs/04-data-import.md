# 04. Импорт данных из XLS/CSV

## Цель

Директор или аналитик УК загружает выгрузку из учетной системы и через минуту видит результат,
а при ошибке — понятный отчет «строка 154: неизвестная единица 'кг.' у товара 'Сыр Моцарелла'».

Какие именно данные нужны и где их взять в iiko / r_keeper / 1С:ERP — в [09](09-data-requirements.md).
Шаблоны ниже — это **каноническая форма**; реальные выгрузки приводятся к ней через профили источников.

## Шаблоны (MVP)

| Шаблон | Ключевые колонки | Частота |
|--------|------------------|---------|
| `restaurants` | код, название, город, формат, дата открытия | разово |
| `products` | код, название, категория, базовая ед., срок годности | при изменениях |
| `suppliers` | код, название, ИНН | при изменениях |
| `menu_items` | код, название, категория, цена | при изменениях |
| `recipes` (ТТК) | блюдо/п/ф, ингредиент, брутто, нетто, ед., действует с | при изменениях |
| `sales` | дата, ресторан, блюдо, кол-во, выручка, скидка | день/неделя |
| `receipts` | дата, ресторан, № накладной, поставщик, товар, кол-во, ед., цена, сумма, НДС | день/неделя |
| `transfers` | дата, откуда, куда, товар, кол-во | по факту |
| `write_offs` | дата, ресторан, товар, кол-во, причина | по факту |
| `inventory_counts` | дата, ресторан, товар, учетный остаток, фактический остаток | по регламенту |
| `supplier_prices` (опц.) | поставщик, товар, цена, действует с/по | при изменениях |

Шаблоны лежат в `templates/` с примером заполнения и листом-инструкцией.

## Маппинг колонок — ключ к реальным выгрузкам

Реальные отчеты iiko/r_keeper не совпадают с нашими шаблонами. Поэтому:
1. При загрузке система распознает колонки (по словарю синонимов + LLM-подсказка) и показывает предпросмотр маппинга.
2. Пользователь подтверждает; маппинг сохраняется как **профиль источника** («Отчет iiko: Движение товаров»)
   и дальше применяется автоматически.
3. Названия товаров из файла сопоставляются с номенклатурой сети (`ProductAlias`): точное совпадение →
   нечеткое (trigram) → предложение ИИ → подтверждение человеком. Несопоставленное не теряется — уходит в M7.

## Пайплайн

```
upload → store raw file (S3) → ImportBatch(pending)
  → parse (тип по расширению, кодировка, разделитель, лист)
  → map columns (профиль источника)
  → validate в staging-таблицах:
       схема/типы → справочные ссылки → единицы → бизнес-правила (дата в периоде, кол-во ≥ 0, сумма = цена×кол-во ±1%)
  → отчет: ошибки (блокируют) / предупреждения (не блокируют)
  → publish: транзакционная замена данных (ресторан × период × тип) — идемпотентно
  → trigger пересчет аналитики для затронутых ресторанов/периодов
```

- Большие файлы обрабатываются фоново, прогресс показывается в UI.
- Каждый batch можно откатить.
- Дубли файлов определяются по хэшу.

## Реализация (этап 2)

Код: `backend/app/imports/` — `templates.py` (шаблоны и синонимы колонок), `reader.py` (CSV/XLSX, поиск строки
заголовков, пропуск итогов), `validate.py` (типы, единицы, ссылки, бизнес-правила; без БД), `service.py` (загрузка,
публикация, откат), `api.py`.

| Правило | Как работает |
|---------|--------------|
| Чтение | CSV в UTF-8 или Windows-1251, разделитель `;` `,` табуляция `|` определяется сам; XLSX — первый лист. Номера строк в отчете совпадают с файлом |
| Что за файл | Можно не указывать: шаблон определяется по заголовку — подходят те, где есть все обязательные колонки, из них берется узнавший больше всего колонок. С выбранным рестораном — среди фактов ресторана, без ресторана — среди справочников |
| Заголовок | Первая строка из первых 30, где нашлись все обязательные колонки (по названию шаблона или синониму). Строки «Итого/Всего» пропускаются с предупреждением; лишние колонки перечисляются в предупреждениях |
| Товар, блюдо, поставщик | По коду → по названию после нормализации (регистр, «ё», знаки, пробелы) → по запомненному соответствию (`NameAlias`). Неузнанное — не ошибка: файл получает статус «Нужно сопоставить названия», а к каждому названию — до 3 похожих позиций справочника. Человек подтверждает один раз; похожее никогда не подставляется молча |
| Единицы | кг/г, л/мл, шт приводятся к базовой единице товара; неизвестная или несовместимая (шт → кг) — ошибка, коэффициент не угадываем |
| Ошибки и предупреждения | Ошибка в любой строке блокирует весь файл (половина файла исказила бы цифры). Предупреждения не блокируют: сумма ≠ цена × количество ±1%, пропущенные итоги, лишние колонки. В отчете — до 200 ошибок |
| Публикация | Только проверенный файл; проверка повторяется (справочники могли измениться). Факты ресторана: строки этого типа за период файла **заменяются** — повторная загрузка не дублирует. Справочники: обновление по коду; ТТК — замена версии (блюдо × «действует с») целиком |
| Сопоставление | `POST /api/imports/{id}/match`: соответствия запоминаются и файл проверяется снова. Сопоставление администратора УК действует на всю сеть, остальных — только на ресторан файла (так выбор одного ресторана не меняет цифры другого; закреплено и в RLS). Похожесть — общие слова с учетом сокращений («оливк.» ~ «оливковое») и триграммы, без ИИ; подсказки ИИ — после шлюза LLM (этап 5) |
| Откат | Удаляет ровно строки этой загрузки. Справочники не откатываются — загружается исправленный файл |
| Доступ | Справочники — только администратор УК; факты — администратор и аналитик УК по всем ресторанам, директор — только свой (RLS) |
| Хранение файла | MVP хранит исходный файл в БД (`import_batches.raw`), объектное хранилище — при реальных объемах |

| Свежесть | По каждому ресторану и виду данных — «по какое число». Зеленое — есть данные за последнюю полную неделю (закупки и списания бывают не каждый день); для инвентаризаций отмечается только отсутствие |

API: `GET /api/imports/templates`, `POST /api/imports` (multipart: `file`, `restaurant_id`, необязательный `template`),
`GET /api/imports`, `GET /api/imports/freshness`, `GET /api/imports/{id}`, `POST /api/imports/{id}/match`,
`POST /api/imports/{id}/publish`, `POST /api/imports/{id}/rollback`, `GET /api/catalog/{product|menu_item|supplier}`.

Экран «Данные» (`frontend/src/app/DataPage.tsx`) работает на этом API: выбор «куда» и «что в файле» (по умолчанию —
определить по файлу), перетаскивание файла, отчет «Мы поняли файл так» (что, куда, период, какие колонки узнали),
ошибки по строкам, загрузка и отмена, таблица свежести по ресторанам, история загрузок. В демо-сборке те же шаги
выполняются в браузере (`frontend/src/api/demoImports.ts`), полная проверка — только на сервере.
